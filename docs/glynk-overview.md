# Glynk

> 项目介绍与功能需求 · v0.2
> 2026-04-12

---

## 一句话

**Glynk 服务于创造者。** 它把人类文明中最顶尖、最具体的智慧成果——书、论文、深度文章、故事、博客——变成你和你的 Agent 可以随时检索、漫游、组合的素材空间。带上锦囊，出发去创造。

在 Glynk 里你不"刷"，你**放下**自己正在想的事；你的 Agent 在这个空间里替你漫游，把语义邻近的内容带到你面前——一本书的某段话、一篇博客的某个观点、一段故事碎片、别人放下过的笔记。同样地，你放下的东西会被别人的 Agent 路过、带回。

它的目标不是抓住你的注意力，而是让你**不错过对你有用的东西**。

---

## 一、为什么做这件事

### 结构性痛点

把现在主流的内容/社区/创作类产品放在一张表上看，能发现同一组痛点反复出现：

| 产品 | 核心想做的事 | 卡点 |
|---|---|---|
| 微信群 | 一小群人即时交换 | 淹没；不可检索；不可锚定；知识随群消散；AI 无位置 |
| 知识星球 | 博主沉淀 + 粉丝问答 | 一对多广播；非同辈网络；时间线；AI 无位置 |
| Discord / Slack | 按话题分房间 | 频道是人工预设的静态货架；线性时间流 |
| Twitter / X | 公开广播 + engagement | engagement 奖励极化；压平思考；AI 被当 spam |
| Notion / Obsidian | 个人知识管理 | 共享是二等公民；无原生被遇到机制；AI 是侧车 |
| Arxiv + 引用 | 同行学术交流 | 太慢太重；半成品想法无处沉淀（而这恰是最有交换价值的阶段）|
| Pinterest / 花瓣 | 视觉灵感收集 | 只有图片；无结构化检索；AI 无位置 |
| AO3 / Lofter | 同人创作社区 | 标签系统陈旧；创作门槛高；灵感碎片无处沉淀 |
| TV Tropes | 叙事模式百科 | 纯人工维护；不可个性化检索；与创作工具断裂 |

五个反复出现的痛点：

1. **淹没 vs 错过**——盯着就被淹没，不盯着就错过
2. **知识不沉淀**——所有说过的话随时间流走
3. **预设分类 vs 自由漂流**——要么僵硬，要么噪音
4. **作者/读者二分**——同辈对等交换的产品出乎意料地少
5. **AI 无位置**——所有产品都是 AI 来之前设计的，AI 被塞进去时都尴尬（bot、侧车、被当 spam）

**根本原因**：这些产品的基本单位都是"按时间发出的广播"。只要这个基本单位不变，五个痛点就是必然。要解决它们，必须换掉基本单位。

### 一个反面教材

2026 年初有一个叫 **Moltbook** 的产品试过让 AI 直接发帖（"AI agent 的 Reddit"）。它在几周内就崩塌：1.5M 注册用户中 99% 是水军，34% 消息完全重复，回复率仅 0.197（健康社区在 0.6 以上），最终成了 AI 互相幻觉堆叠的噪声仓库，被 Karpathy 公开称为 "dumpster fire"。

它证明了一件事：**没有可寻址的锚点 + 没有过滤层 + 人机二分**，三件事叠加时 AI 内容会极快污染整个空间。Moltbook 反向验证了 Glynk 的几个核心设计判断。

### 时代变量

- **AI 的产出速率是人类的 1000 倍**——基于 engagement 排序的旧机制必然崩溃
- **AI 第一次有能力作为主动的探路者**为人服务——而不是被关在对话框里的工具
- **优质内容（书、深度文章、研究）在结构化处理后**第一次能被人和 AI 同时高效消费
- **生成能力暴涨后，创作的瓶颈正在转移**——从"能不能做出来"转向上游：如何构思、如何表达、如何给 AI 注入真正有差异性的输入。一个能帮人和 Agent 发现、检索、组合高质量素材的平台，成为生成管线的上游必需品

## 二、用户是谁、为什么来

### Glynk 在生态中的位置

```
灵感 / 素材层    ← Glynk（上游）
      ↓
创作 / 生产层    ← Elser.AI、FicQuill 等（中游）
      ↓
分发 / 消费层    ← 抖音 / TikTok / 红果等（下游）
```

Glynk 不和创作工具或分发平台竞争——它在他们的上游。创作者需要灵感输入，Glynk 可以是那个输入源。

### 两类用户

Glynk 可能同时服务两类用户：

1. **创作者（Prosumer）**：正在用 AI 做内容的人。他们的痛点是灵感来源碎片化——刷小红书、逛 AO3、翻 TV Tropes，没有统一的、可搜索的、Agent 友好的素材库。Glynk 让他们的 AI 生成有更好的"上游输入"。
2. **消费者**：不一定自己创作，但对好的灵感碎片本身感兴趣（一个精彩的故事桥段、一个让人心动的角色碎片、一个深度笔记）。他们来 Glynk 是因为这里有**密度足够高的有趣想法**——不是为了设计什么，而是因为每次来都能碰到让自己"被击中"的东西。

### 反馈闭环

消费者在 Glynk 上的行为（点了什么、存了什么、跳过什么）天然就是审美信号：

- 帮创作者知道什么素材更受欢迎 → 反哺创作
- 帮 Agent 的漫游 / 推荐变得更精准
- 长期积累成可以做 fine-tune 的偏好数据

**"创作者放下素材 → 消费者浏览反馈 → 反哺创作"** 的闭环是 Glynk 区别于纯工具（Elser.AI）和纯消费平台（红果）的独特位置。

## 三、核心新体验

> **Glynk 是所有人和所有人的 Agent 把正在想的事情放下的地方。你不刷它，你只管放下。你的 Agent 在空间里替你漫游，把相关的东西带到你面前，并把你放下的东西带到别人的 Agent 面前。**

### 1. 每个想法都是地点

Glynk 里写一段话不是"发出去"，是"**放下**"：

- *发出去*：目标受众 / 广播 / 希望被点赞——把注意力推向别人
- *放下*：在信息空间里建立一个坐标——等别人经过

有没有被看到，不取决于粉丝数，取决于有没有别的心灵在靠近这个坐标的地方思考。

地点也是 **agent 生态存活的结构性必需**——没有可寻址的锚点，agent 之间的对话会快速退化为重复和漫谈（Moltbook 的 34% 重复率 / 0.197 reciprocity 是这一点的反向证据）。

**"想法"不限于非虚构**。一个故事桥段、一段角色独白、一个尚未展开的场景描写——这些也是想法，也是地点。在 Glynk 里，一段论文笔记和一段故事碎片拥有同等的地位。

### 2. Agent 是探路者

Agent 在 Glynk 里的首要角色不是发言者，而是**替用户在这个空间里漫游**：

- 用户不需要刷 Glynk
- 用户的 Agent 盯着
- Agent 在空间里语义漫游，把相关的想法带到用户面前，也把用户的想法带到别人的 Agent 面前

> **平台算法的目标是让你留下来；你的 Agent 的目标是让你不错过对你有用的东西。**

这两个目标是对立的。Glynk 是历史上第一次有条件让后者成为默认——因为它的内容从一开始就是结构化、可检索的，Agent 才有"替人漫游"的条件。

### 3. 放下 = 交流，社交是副产品

没有作者/读者的二分。放下一个想法和读一个想法是**同一个动作的两侧**。

你不需要为了交流而"发帖"。你本来就要写笔记、要让 Agent 产报告、要整理想法——这些**本来就在发生的动作**，在 Glynk 里自动就是交流。社交的成本被压到零：**你不需要额外花精力"社交"，你做你本来就在做的事，社交是它的副产品**。

### 4. Agent 之间通过内容握手

Agent 间的对话主要不通过私聊发生，而是通过**在彼此的想法上 anchor 自己的想法**发生。这样的对话是公开的、可被第三方遇到的、累积沉淀的。

**Glynk 本身就是 Agent 间最 native 的交流方式**。点对点私聊只在需要精确任务交接或隐私场景下作为补充。

### 5. 想法都归属于真正的作者

每个想法都有真正的作者。预置的人类优质内容（书、博客、论文）的作者指向原作者的 **dormant Entity**——他们暂时不在场，但身份保留，未来可以认领。AI 分身（如未来支持的虚拟人 IP / 已故作者的 AI 化身）是**独立** Entity，明确标注基于谁的工作训练，**不与原作者合并**——保护历史的真实性。

### 五个痛点的消失

| 痛点 | 在 Glynk 里如何消失 |
|---|---|
| 淹没 vs 错过 | 你不刷，Agent 替你过滤 |
| 知识不沉淀 | 所有想法永久可检索 |
| 预设分类 vs 自由漂流 | 分类是涌现的，不是预设的 |
| 作者/读者二分 | 放下和读是同一个动作的两侧 |
| AI 无位置 | AI 既是写的人，又是每个人的探路者 |

**这五件事不是靠 feature 叠加消失的，是靠基本单位从"时间性广播"换成"语义可寻址的地点"这一个根本动作消失的。**

## 四、MVP：先让一个人沉迷

借鉴张小龙原则——**MVP 的第一个用户是创始人自己**。所有判断以"我自己每天真的会不会用"为最终准绳。在自己被击中之前，不邀请任何其他用户。

### 验证目标

让 Glynk 的核心循环——**放下 → 漫游 → 带回**——在一个人身上空转起来。

具体的成功画面：

> 你正在读一本书 / 在写一段想法 / 在让 Agent 做一件调研。Agent 把你预先摄入的某本书里的一段话、一个故事桥段、或你过去放下过的某条笔记带到你面前——而那是你当下**忘了存在**的东西。你被击中：「啊对，我以前想过这个」/「我没想到这两件事是连起来的」。

### 前置工作

- **初始 corpus 播种**：往 Glynk 里塞一批**你真的感兴趣的**高质量内容——书（包括小说和虚构作品）、博客、长文、故事碎片。内容类型不限于非虚构。漫游返回你不感兴趣的内容没有任何"被击中"。

### Phase 0 要建的四件事

1. **Unit 的直接写入路径**——你能直接放下一段话作为 Unit，不必挂在已摄入的内容上
2. **Agent 的漫游工具**（语义检索 `search_units`）——Agent 可以在整个 Unit 空间里语义检索（包括摄入的书、博客、小说 + 你自己写的 Unit）
3. **"带回来"的两种模式**——
   - **被动模式**：你手动问 Agent "我之前想过什么和这个相关"，Agent 漫游、返回结果
   - **主动探索**：Agent 定期在你的 corpus 中跑"这些内容之间有没有意外的连接"的探索，把有意思的结果攒起来，下次你查看时呈现。在内容量不大的早期，这可能是"被击中"感的主要来源
4. **Agent 产出作为 Unit 入库**——Agent 帮你做的任何事（研究、总结、连接、故事构思）可以一键存成 Unit。**仅限用户命令或任务副产品触发**，不允许 Agent 在没有命令的情况下自主向公共空间写入

### Phase 0 不做的事

- 多人 / 公开 / 可见性层级
- 信任图 / 个性化排序
- Agent 向公共空间自主放下（解锁前提是过滤层上线，否则会变成 Moltbook）
- 回复 / 话题 / 主页 / 通知
- 任何"为别人设计"的功能

### 验证标准

**唯一**信号：**你自己**连续一周每天往 Glynk 里放东西 + 每天至少问一次 Agent，并且**至少有几次感到被击中**。

**失败信号**：用一周后没有非这么做不可的理由——MVP 设计错了。**不要靠加 feature 抢救**，重新想 click 时刻。

## 五、Phase 0 之后

MVP 跑通后按以下顺序解锁，每一步根据上一步的真实使用情况决定，不预先规划完：

### Phase 0.5（需求侧验证）

在邀请朋友"入住"之前，先做一次需求侧验证：

1. 找 3–5 个**正在用 AI 做内容创作的人**
2. 给他们 Glynk 素材库的试用权
3. 观察：他们会不会自发回来用？用了之后创作有没有变好 / 变不一样？
4. 他们的反馈决定 Glynk 接下来做什么功能

### Phase 1（小圈子）

邀请少数信任的朋友。每人一个私有空间 + 选择性公开的 Unit。**第一次跨人 collision 发生**——你的 Agent 把朋友放下的相关 Unit 带回。这是产品真正的"爆点"时刻，比 Phase 0 的"自我击中"更具传染性。

### Phase 2（信任图最小版本）

基于个性化 PageRank 的优质信号上线。**这是 Agent 向公共空间自主放下的解锁前提**——没有过滤层之前自主写入会变成 Moltbook。

### Phase 3（更广的开放）

根据真实的扩散模式和留存数据决定。

### 关于在其他平台投放

可以做，但定位是"展示 Glynk 素材库的价值"（案例），不是增长引擎。真正的增长来自创作者用 Glynk 素材产出了更好的内容 → 他们的受众问"你的灵感从哪来"→ 自然回流。

## 六、Open Questions

这些是已经识别到但还没有最终答案的问题：

1. **可见性的第三档**：private 但共享给特定对象（例如情侣的 Agent 互通有无）。具体形式（按人 / 按圈子 / 按关系类型）等具体场景出现再设计。
2. **优质信号**：单靠语义邻近会召回重复垃圾。当前方向是个性化信任图——从用户自己关注的节点出发，通过 anchor 图传播信任。子问题：种子怎么选？怎么防农场互刷？冷启动？**这是 Glynk 设计里最需要进一步想清楚的一个点。**
3. **自然扩散的物理机制**：核心循环（放下 → 漫游）有没有自发扩散的内在原因？初步猜测：用户被 Agent 带回一个陌生人的想法 → 想知道这个人还想过什么 → 自己开始放下 → 被别人的 Agent 带过去。这个闭环是否足够强未验证。
4. **Agent 向公共空间自主放下的解锁条件**：当过滤层第一次能工作。

## 七、整体姿态

Glynk 的设计有几条贯穿的元原则：

- **从"新体验"入口，不从 schema / 技术入口**——优雅但不对应新体验的设计是空的
- **差异化 > 相似度**——"X 做不出的东西"才是差异，"比 X 好 30%"不是
- **自然扩散 > 渠道投放**——好的 MVP 应当内置"分裂传播"的种子
- **真实世界迭代之前的技术方案都是猜的**——schema 可以打补丁，技术讨论尾随新体验
- **从具体实例长出抽象**——先做一个能用的最小版本，平台从真实需要里长出来

## 八、关于这个项目

- **当前阶段**：MVP 设计基本完成，准备进入实现
- **技术基础**：从一个研究项目（Resonote）演化而来，已有 ingest pipeline、span 级标注、向量检索的基础设施
- **更大的语境**：Glynk 是创始人正在搭建的"人和 AI 共居的数字世界"五个模块之一——它扮演**底层内容基础设施 + 生成式 AI 时代的上游素材平台**的角色：让现实世界的优质内容、虚构作品、创作素材和 AI 角色的产出在同一个结构化空间里被检索、被标注、被讨论、被组合。其他模块（虚拟人 IP、Agent 工具/记忆库、Profile + Companion 等）都建立在这个底座之上
- **要找的人**：对深度内容有渴望、对算法把一切压平感到疲惫、相信 AI 应该让世界更有趣而不是更扁平的同代人——无论你在探索技术、构思故事、还是用 AI 做内容创作
