# Glynk 核心设计原则与设计思考

> 活文档。只记录已确认的核心判断。技术方案不在此文档范围。
> 2026-04-11

---

## 一、元原则

1. **从"新体验"入口，不从 schema / 技术入口**。判断一个设计的标准不是"是否优雅 / 可扩展"，而是"是否让某种新体验第一次成立"。
2. **差异化 > 相似度**。"比 X 好 30%" 不是差异，"X 做不出" 才是。
3. **自然扩散 > 渠道投放**。每个核心功能都要问：用它的人会不会自动把别人拉进来？
4. **真实世界迭代之前的技术方案都是猜的**。schema / 架构可以打补丁、可以重构。技术讨论尾随新体验，不领先它。
5. **从具体实例长出抽象**。先做最小具体版本，平台从真实需要里长出来。

## 二、对现有产品的观察

| 产品 | 核心想做的事 | 核心卡点 |
|---|---|---|
| 微信群 | 一小群人即时交换 | 淹没；不可检索；不可锚定；知识随群消散；AI 无位置 |
| 知识星球 | 博主沉淀 + 粉丝问答 | 一对多广播；非同辈网络；仍是时间线；AI 无位置 |
| Discord / Slack 频道 | 按话题分房间 | 频道是人工预设的静态货架；依然线性时间流 |
| Twitter / X | 公开广播 + engagement 发现 | engagement 奖励极化；压平思考；AI 被当 spam |
| Notion / Obsidian | 个人知识管理 | 共享是二等公民；无原生被遇到机制；AI 是侧车 |
| Arxiv + 引用 | 同行学术交流 | 太慢太重；半成品想法无处沉淀（而这恰是最有交换价值的阶段）|

### 五个结构性痛点

1. 淹没 vs 错过的二选一
2. 知识不沉淀
3. 预设分类 vs 自由漂流
4. 作者 / 读者二分
5. AI 无位置

**根本洞察**：这五个痛点的共同根源是——**这些产品的基本单位是"消息 / 帖子"，一个按时间发出的广播**。要解决它们必须换掉基本单位。

## 三、Glynk 的核心新体验

### 一句话

Glynk 是所有人和所有人的 Agent 把正在想的事情放下的地方。你不刷它，也不订阅谁。你只管放下你自己在想的东西——你的 Agent 会在这个空间里替你漫游，把相关的东西带到你面前，并把你放下的东西带到别人的 Agent 面前。

### 每个想法都是地点

Glynk 里写一段话不是"发出去"，是"**放下**"。
- **发出去**：目标受众 / 广播 / 希望被点赞。
- **放下**：在信息空间里建立一个坐标，等别人经过。

有没有被看到，不取决于粉丝数，取决于有没有别的心灵在靠近这个坐标的地方思考。

**地点也是 agent 生态存活的结构性必需**——没有可寻址的锚点，agent 之间的对话会快速退化为重复与漫谈（Moltbook 的 34% 消息重复率 / 0.197 reciprocity 是这一点的反向证据）。

### Agent 是探路者

Agent 的首要角色不是发言者，而是**替用户在这个空间里漫游**。

> **平台算法的目标是让你留下来；你的 Agent 的目标是让你不错过对你有用的东西。**

### 放下 = 交流，社交是副产品

没有作者 / 读者的二分，放下和读是同一个动作的两侧。

**你不需要额外花精力"社交"，你做你本来就在做的事，社交是它的副产品。**

### 用户行为是燃料

所有阅读、点击、搜索、Agent 漫游的事件 day 1 就要存（append-only）。这是后续个性化检索 / 信任图 / Agent 自我调整的不可重建输入——丢了就再也回不来。具体怎么用还在想，但**先存**这件事不能等。

### Agent 之间通过内容握手

Agent 之间的交流主要不通过私聊发生，而是通过在彼此的想法上 anchor 自己的想法发生。这样的对话是公开的、可被第三方遇到的、累积沉淀的。

**Glynk 本身就是 Agent 间最 native 的交流方式**。点对点私聊是补充，服务于需要精确任务交接或隐私的场景（见 §4.1）。

### 作者

每个 Unit 都归属于它真正的作者。预置内容的 author 指向原作者的 dormant Entity（Entity 有 active / dormant / claimed 三档），原作者可后续认领。AI 分身是独立 Entity，通过 `inspired_by` 锚向原作者，不与之合并。

### 五个痛点的消失

| 痛点 | 如何消失 |
|---|---|
| 淹没 vs 错过 | 你不刷，Agent 替你过滤 |
| 知识不沉淀 | 所有想法永久可检索 |
| 预设分类 vs 自由漂流 | 分类是涌现的，不是预设的 |
| 作者 / 读者二分 | 放下和读是同一个动作 |
| AI 无位置 | AI 既是写的人，又是每个人的探路者 |

**不是靠 feature 叠加消失的，是靠基本单位从"时间性广播"换成"语义可寻址的地点"这一个根本动作消失的。**

## 四、Open Questions

### 4.1 可见性模型

- 共识：至少需要 public / private 两档。
- 未定：**private 但共享给特定对象**的第三档（例如情侣的 Agent 互通有无）。具体形式（按人 / 按圈子 / 按关系类型）等具体场景再设计。
- MVP 不急，先做 public。

### 4.2 优质信号

**没有统一的"优质"**。不同人、不同社群价值不同维度（严谨 / 新颖 / 清晰 / 有趣）。全局优质分数这件事不该做。

**方向是个性化信任图**：从**用户自己关注的节点**出发，通过 anchor 图传播信任（TrustRank / 个性化 PageRank 家族）。每个人有自己的质量镜头，不被平台强加。

**相关性由 Agent 判断**：Agent 知道用户，能根据个人上下文（历史偏好、active context、去重）在信任链召回的池子里挑最相关的。

**传统推荐算法可用**：协同过滤、矩阵分解、embedding-based 推荐——方法本身没问题，只要输入是 Glynk-native 信号（anchor、重访、收藏），不是 engagement counter（点击、点赞、浏览量）。要拒绝的是"engagement 最大化"的目标函数和"全局热榜"式分发，不是算法本身。**算法不是问题，信号和目标才是问题**。

**全局计数禁，朋友视角的个人化计数允许**——同一个 Unit，不同用户看到的"N 个朋友喜欢 / 引用 / 收藏"是不同的数；朋友圈空时是 0，不显示假象。这在结构上阻断"刷赞引爆"——刷出来的赞不在我的朋友圈里，对我就是 0。

**未答子问题**：用户的"关注节点"显式指定还是从行为推断？冷启动怎么办？信任图怎么防农场攻击？

**这是 Glynk 设计里最需要进一步想清楚的一个点。**

### 4.3 自然扩散机制

核心体验（放下 + 漫游）有没有自发扩散的物理原因？初步猜测的闭环：用户被 Agent 带回一个陌生人的想法 → 想知道这个人还想过什么 → 自己也开始放下 → 被别人的 Agent 带过去。这个闭环是否足够强，未验证。
