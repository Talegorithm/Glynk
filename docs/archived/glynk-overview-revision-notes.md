## 修改 1：一句话定位——不要太窄

**当前问题**：定位为"严肃思考的人"太窄、太无聊，和 Notion/Obsidian 直接竞争

**方向**："思考者平台"要改掉，但也不要改成另一个同样窄的定位（比如"灵感基础设施"也偏窄）。Glynk 应该是一个包括但不限于灵感素材的内容平台——思考、创作灵感、故事碎片都是它的内容类型。

**具体操作**：修改 §一句话（第 9-13 行），把"严肃思考的人"改为更包容的用户描述，让"研究者"和"故事构思者"和"内容创作者"都能看到自己。

## 修改 2：§二.1 "每个想法都是地点"——扩展"想法"的范围

**当前问题**：只暗示想法是非虚构笔记/观点

**方向**：在这一节末尾加一段，明确说"想法"包括故事桥段、角色碎片、场景描写、情绪节拍等创作素材。它们和论文笔记在 Glynk 里拥有同等地位。

**具体操作**：在 §二.1 末尾补一段，类似：

> "想法"不限于非虚构。一个故事桥段、一段角色独白、一个尚未展开的场景描写——这些也是想法，也是地点。在 Glynk 里，一段论文笔记和一段"花火哑火了"的故事碎片拥有同等的地位。

## 修改 3：§一 痛点表——补充创作侧的产品对比

**当前问题**：只列了消费/交流侧的产品（微信群、知识星球等），没有创作工具的对比

**方向**：加两三行创作侧的产品，让痛点分析同时覆盖"思考者"和"创作者"

**具体操作**：在痛点表中加入：

| 产品 | 核心想做的事 | 卡点 |
|---|---|---|
| Pinterest / 花瓣 | 视觉灵感收集 | 只有图片；无结构化检索；AI 无位置 |
| AO3 / Lofter | 同人创作社区 | 标签系统陈旧；创作门槛高；灵感碎片无处沉淀 |
| TV Tropes | 叙事模式百科 | 纯人工维护；不可个性化检索；与创作工具断裂 |

## 修改 4：§一 时代变量——加入"生成瓶颈转移"

**当前问题**：三个时代变量都偏"AI 产出"侧，没有提到生成能力暴涨后瓶颈的转移

**方向**：加一条。注意不要把它窄化为"知道自己想要什么"——瓶颈是多层的：知道自己想要什么、把需求准确传达给 AI、弥合"想要的"和"表达出来的"之间的 gap、以及如何让自回归模型产出真正创新的（而非重组已有 pattern 的）内容。不需要全部展开，但表述要有足够的宽度。

**具体操作**：在时代变量部分加第四条，大意为：

> 生成能力暴涨后，创作的瓶颈正在从"能不能做出来"转向上游——如何构思、如何表达、如何给 AI 注入真正有差异性的输入。一个能帮人和 Agent 发现、检索、组合高质量创作素材的平台，成为生成管线的上游必需品。

## 修改 5：§三 MVP corpus 播种——加入创作/故事内容 + 探索机制

**当前问题**：只提到"20-50 本书 + 100-500 篇博客"，全是非虚构

**方向**：
1. 内容类型应包括小说、虚构作品、故事碎片
2. 更重要的是：在内容量不大的早期，不能只靠现有的 hook+embed 机制做检索。应该让 Agent 主动去探索、发现内容之间的**连接可能性**——不是等用户问"有什么和这个相关"，而是 Agent 自己去跑一些组合、发现一些跨内容的意外关联。这可能是早期"被击中"感的主要来源。

**具体操作**：
1. 把 corpus 描述改为包含虚构作品
2. 在 Phase 0 的"带回来"机制描述中，考虑加入"Agent 主动探索连接可能性"作为一种补充模式——即使用户没有主动问，Agent 也可以定期跑一些"这些内容之间有没有意外的连接"的探索，然后把有意思的结果攒起来，等用户下次查看时呈现

## 修改 7（新增）：需求侧思考——Glynk 的用户是谁、为什么来

> 来源：0412 深夜讨论，受刘耕/Elser.AI 访谈启发（`37c1763ead18a171`）

**当前问题**：现有文档几乎全是供给侧思考（内容怎么结构化、怎么检索、怎么漫游），对"谁来用、为什么来、为什么留下"缺少明确回答。刘耕的警告："工具不会天然导向社区。Day 1 就要想清楚。"

**Glynk 在生态中的位置**：

```
灵感/素材层    ← Glynk（上游）
    ↓
创作/生产层    ← Elser.AI、FicQuill 等（中游）
    ↓
分发/消费层    ← 抖音/TikTok/红果等（下游）
```

Glynk 不和 Elser.AI 或红果竞争——它在他们的上游。Elser.AI 的 Prosumer 需要灵感输入，Glynk 可以是那个输入源。

**需求侧假设**：

Glynk 可能同时服务两类用户：

1. **创作者（Prosumer）**：正在用 AI 做内容的人。他们的痛点是灵感来源碎片化——刷小红书、逛 AO3、翻 TV Tropes，没有统一的、可搜索的、Agent 友好的素材库。Glynk 让他们的 AI 生成有更好的"上游输入"。
2. **消费者**：不一定自己创作，但对好的灵感碎片本身感兴趣（一个精彩的故事桥段、一个让人心动的角色碎片、一个深度笔记）。他们来 Glynk 是因为这里有**密度足够高的有趣想法**——不是为了设计什么，而是因为每次来都能碰到让自己"被击中"的东西。

**消费者的审美反馈闭环**（重要）：

消费者在 Glynk 上的行为（点了什么、存了什么、跳过什么）天然就是审美信号。这个信号可以：
- 帮创作者知道什么素材更受欢迎 → 反哺创作
- 帮 Agent 的漫游/推荐变得更精准
- 长期积累成可以做 fine-tune 的偏好数据

这个"创作者放下素材 → 消费者浏览反馈 → 反哺创作"的闭环是 Glynk 区别于纯工具（Elser.AI）和纯消费平台（红果）的独特位置。

**需求侧验证动作**（建议加入 Phase 0 之后）：

Phase 0 验证的是"我自己想不想用"。Phase 0 通过后，在进入 Phase 1（小圈子）之前，加一个需求侧验证步骤：

1. 找 3-5 个正在用 AI 做内容创作的人（一番可以推荐、酒馆社群里可以找、公司同事）
2. 给他们 Glynk 素材库的试用权
3. 观察：他们会不会自发回来用？用了之后创作有没有变好/变不一样？
4. 他们的反馈决定 Glynk 接下来做什么功能

**关于在其他平台投放**：可以做，但定位是"展示 Glynk 素材库的价值"（案例），不是增长引擎。真正的增长来自创作者用 Glynk 素材产出了更好的内容 → 他们的受众问"你的灵感从哪来"→ 自然回流。

## 修改的核心逻辑（更新）

两件事：
1. 让 Glynk 从第一天起就能容纳故事/创作内容，而不只是非虚构笔记（技术零改动，可能性空间翻倍）
2. 在 Phase 0 之后加入需求侧验证——找真实的 AI 创作者试用，看他们会不会回来（供给侧做得再好，没人来就是空转）
