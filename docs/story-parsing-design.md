# 故事解析设计

> 基于 2026-04-13 讨论，从需求侧出发的故事素材提取设计
> 前置文档：`glynk-story-parsing-agent.md`（数据模型与基本任务定义）

---

## 一、设计原则

### 目标不是还原故事，是备好弹药

故事解析的产出物是**创作者的灵感弹药库**。判断每个派生 Unit 好不好的标准只有一个：创作者在需要的时候能不能找到它、找到之后能不能被击中。

这意味着：

1. **从需求侧设计**——先想创作者会搜什么，再决定提取什么、怎么写描述
2. **描述比分类重要**——material_type 指导提取过程，但素材能不能被找到靠的是 body 的写法
3. **说人话**——body 里的语言应该是创作者聊天时会说的话，不是文学批评术语

### 三层信息架构

每个派生 Unit 的信息分三层，对应不同的用途和受众：

| 层 | 内容 | 面向谁 | 作用 |
|---|---|---|---|
| **展示层** | 原文片段 + 基本描述 | 所有用户 | 让创作者被"击中" |
| **分析层** | 手法解读 + 可迁移种子 | 注册用户 | 让创作者理解"为什么管用"并能用到自己作品里 |
| **检索层** | 效果标签、感受词、跨作品关联、创作场景适用性 | 搜索系统内部 | 驱动搜索匹配质量 |

三层都是 Unit 的数据字段，不涉及代码层面的开闭源区分。检索层的价值不在于"隐藏"，而在于它是**不断从用户行为（搜索、点击、收藏）中增强的运营数据**——壁垒来自积累，不来自保密。

> **关于开闭源**：当前阶段闭源开发，优先验证产品。壁垒不在代码而在积累的素材库、用户数据和社区。未来如需 Agent 生态互通，通过开放 API 实现，不依赖开源代码。

## 二、素材类型体系

### 三层十类

类型是**提取侧**的工具——指导解析 Agent "从这个故事里找什么"。创作者搜索时不按类型搜，按感受/效果/困境搜。

#### 第一层：故事元素——这个故事里有什么

| material_type | 说明 | 典型搜索 query |
|---|---|---|
| `character` | 角色的核心矛盾、标志性行为、性格光谱 | "隐藏实力的天才"、"在旧体系里用错误方法做对事的异类" |
| `relationship` | 两个角色之间的张力模式和演变轨迹 | "从互相利用到真正信任"、"师徒反目" |
| `scene` | 有画面感的空间/时刻——光线、气味、声音、情绪 | "雨天的废弃实验室"、"黎明前的战场余烬" |
| `dialogue` | 能结晶角色或主题的台词 | "反派的自我辩白"、"沉默中说出的告白" |
| `setting` | 有趣的规则、机制、文化细节 | "有代价的魔法体系"、"赛博朋克底层的阶层潜规则" |

#### 第二层：叙事手法——故事是怎么做到的

| material_type | 说明 | 典型搜索 query |
|---|---|---|
| `beat` | 具体的戏剧转折——价值极性翻转的瞬间 | "被信任的人背叛的揭露时刻"、"以为赢了其实输了" |
| `mechanism` | 结构性装置——安放一次、持续产生张力 | "信息不对称的限制设计"、"双重身份的压力装置" |
| `trope` | 跨作品的结构性叙事模式 | "反派其实是对的"、"英雄必须变成他最恨的人" |
| `arc` | 情感在一段叙事中演变的形状 | "从仇恨到理解的转变弧线"、"先给希望再全部夺走" |

#### 第三层：主题——故事在问什么

| material_type | 说明 | 典型搜索 query |
|---|---|---|
| `question` | 故事真正在追问的问题 | "AI超越人类后人的意义"、"为多数人可以牺牲少数人吗" |

类型仍是**开集**——通过 `metadata.material_type` 标记，未来可以增加新类型。

### 双层粒度

character、relationship、arc 三个类型采用**画像 + 实例**双层结构：

```
角色画像 Unit（汇总层，一个角色一个）
  ├── 角色时刻 Unit  anchor(role=instance_of)
  ├── 角色时刻 Unit  anchor(role=instance_of)
  └── 角色时刻 Unit  anchor(role=instance_of)
```

- **画像/动态层**：回答"这个角色/关系有什么意思"——构思阶段找方向时命中
- **时刻/节拍层**：回答"具体哪个场景体现了这一点"——执行阶段找参考时命中

其余类型（scene, dialogue, beat, mechanism, trope, setting, question）通常为单层。

## 三、Body 写作规范

### 核心原则：说创作者的语言

Body 是素材能不能被找到的关键。它需要自然地包含三类词汇：

- **感受词**：心疼、窒息、燃、空虚、被击中……
- **效果词**：让人停不下来、让玩家吵起来、读完想重看……
- **创作困境词**：太套路、太突兀、没有张力、像工具人……

不是刻意塞关键词，而是好的描述本身就应该传达"这段让你有什么感觉"。

### 具体行为 > 抽象标签

```
❌ "她很勇敢"
✅ "被威胁时她会先笑一下，然后用最平静的语气说出最狠的话"

❌ "师徒关系破裂"
✅ "老师发现学生在用他教的剑法保护他最痛恨的人——
    而学生的剑法已经比他更好"

❌ "反派洗白"
✅ "你翻回前面的章节，发现他做的每一件'恶事'都是在延缓
    一个更大的灾难——而他选择不告诉任何人"
```

### 示例：完整的 body

以"哑巴军师困境"（mechanism 类型）为例：

**展示层**（公开）：
> 主角携带一个强大的 AI 顾问，但它只能通过文字交流——不能语音、不能即时。每次战斗中需要紧急策略时，主角必须用宝贵的行动时间去"写字问问题"，而回复还会延迟若干回合到达。AI 是延迟召唤的智库，不是自动战斗外挂。

**分析层**（注册用户）：
> 这个限制让 AI 同伴既强大又笨拙，把每次求助变成一个有代价的决策——值不值得在战斗中冒险停下来？信息优势和时间劣势之间的权衡贯穿整个故事，持续产生新的戏剧冲突，同时让主角不能依赖外挂、必须独立决策，性格被逼出来。
>
> 可迁移种子："强能力 + 窄通道"——给角色一个很强的资源，但在最需要它的时刻让接口成为瓶颈。适用于任何需要让辅助力量不变成外挂的场景。

**检索层**（仅内部）：
> 效果：制造反复的紧张决策、防止辅助角色 overpowered、逼出主角独立性格
> 感受：焦急、"快点快点来不及了"、战略性紧张
> 创作场景：设计有约束的能力体系、让配角/工具不抢主角戏份、在战斗中制造思考空间
> 关联模式：能力代价设计、信息不对称、"有税的资源"

## 四、创作者视角验证

为验证素材体系和 body 写法是否真正服务于创作者，以下用三个创作者角色的具体工作场景做推演。

### 角色 A：AI 虚拟人设计者

设计在社交平台上有人格的 AI 角色。

**时刻 1：人设方向（构思阶段）**

| | |
|---|---|
| 已知 | 目标平台、受众画像、大致方向 |
| 困境 | 不知道什么样的人格能让人持续关注 |
| 会搜 | "什么样的角色让人想一直看下去" |
| 需要的素材 | character 画像——重点是"为什么这个角色有吸引力"的机制分析 |

示例匹配——从《我的天才女友》提取的 character Unit：

> 莉拉让人无法停止关注，不是因为她聪明，而是因为她总是在你以为她会做 A 的时候做 B——而且 B 比 A 更对。她的不可预测不是随机的，是因为她的判断力比读者快一步。你永远在追她的思路。
>
> 吸引力机制是"智力落差带来的好奇心"——读者始终觉得"我还没完全理解她"，所以不舍得走。前提是她的选择事后看必须是对的，否则从"难以预测"变成"人格分裂"。

**时刻 2：说话风格（执行阶段）**

| | |
|---|---|
| 已知 | 人格方向已定——"毒舌但有洞察力" |
| 困境 | 需要具体的说话习惯参考 |
| 会搜 | "嘴硬心软的角色怎么说话" |
| 需要的素材 | dialogue / character 时刻——具体的台词结构和行为反差 |

示例匹配——从《银魂》提取的 dialogue Unit：

> 神乐被问"你担心他吗"时回答："才没有，那种蠢货死了正好给我省口粮。"但她说这话的时候已经在穿鞋出门了。
>
> 台词和行动的反差——嘴上说的和身体做的刚好相反。这给出了一个可以直接偷走的句式结构：否认 + 贬低，同时身体在做否认内容的反面。

### 角色 B：网文 / 编剧作者

写长篇故事，需要从大纲到具体场景的全流程素材。

**时刻 1：主角成长线设计（构思阶段）**

| | |
|---|---|
| 已知 | 要写废材逆袭的修仙文 |
| 困境 | 这条线太套路了 |
| 会搜 | "废材逆袭但不俗套的写法" |
| 需要的素材 | arc / mechanism——替代性的成长弧线设计 |

示例匹配——从《凡人修仙传》提取的 arc Unit：

> 韩立不是废材逆袭——他是资质平庸者的长期主义胜利。他的金手指不是某个外挂能力，而是他比所有人都更愿意花时间。天才们在高处博弈、内斗、走捷径然后死了，韩立一步一步爬，活到了最后。
>
> 这条线的独特满足感不在"打脸"，在"时间证明了一切"。读者要等几百章才能感受到——但这种满足比瞬间爽点更持久，因为读者和韩立一起走过了那些时间。
>
> 可迁移种子："反金手指"——主角的优势不是一个能力而是一种品质。需要更长的叙事来兑现，但兑现时的重量成正比。

**时刻 2：信任建立的场景（执行阶段）**

| | |
|---|---|
| 已知 | 两个角色从互相提防到信任，需要写那个转折场景 |
| 困境 | 不知道怎么让这个转变不突兀 |
| 会搜 | "从敌对到信任的转折怎么写得自然" |
| 需要的素材 | beat / scene——具体的信任建立场景和技巧 |

示例匹配——从《冰与火之歌》提取的 beat Unit：

> Jaime 在浴池里向 Brienne 说出弑君真相。它管用不是因为他"说了真话"——而是因为他选择了一个极度脆弱的时刻（赤裸、伤残、发烧）和一个他最不需要讨好的人来说。信任不是靠"我告诉你一个秘密"建立的，是靠"我在最没有防御的时候把最难堪的部分给你看"建立的。
>
> 技巧：让角色先失去所有伪装（不是主动卸下，是被环境剥掉的），然后在这个无法伪装的状态下让真话"溢出来"。读者不会觉得"他决定坦白"，而是"他终于撑不住了"——后者比前者真实得多。

### 角色 C：跑团 GM / 剧本杀作者

准备互动叙事体验，需要设计局势、NPC 和选择。

**时刻 1：设计递进威胁（构思阶段）**

| | |
|---|---|
| 已知 | 玩家上次得罪了一个有权势的 NPC |
| 困境 | 需要一个逐步逼近的后果结构 |
| 会搜 | "权力压迫怎么一步步收紧" |
| 需要的素材 | mechanism / arc——威胁升级的结构性模式 |

**时刻 2：设计道德困境（执行阶段）**

| | |
|---|---|
| 已知 | 今晚高潮需要一个两难选择 |
| 困境 | 想不到好的两难 |
| 会搜 | "没有正确答案的选择"、"让玩家吵起来的道德困境" |
| 需要的素材 | beat / question——具体的两难设计及其原理 |

示例匹配——从《巫师 3》提取的 beat Unit：

> 林中之心任务：一个树灵被封印在树中。它说释放它能救一个孤儿院的孩子。但释放它意味着附近村庄被诅咒。你后来发现——释放了它，孩子被救了，村庄的人全死了；没释放它，村庄安全了，孩子被吃了。
>
> 这个困境"让人吵起来"是因为两个选项的后果都只在事后揭晓，而且各自牺牲了一群无辜的人。没有清晰天平——是"一群孩子 vs 一个村庄"，怎么选都后悔。
>
> 设计要点：好的两难不是"好 vs 坏"，是"好 vs 好"或"坏 vs 坏"。后果必须具体到人（不是"有人会死"，是"那个你之前帮过的老太太会死"）。

### 从三个角色的练习中发现的规律

**1. 构思 vs 执行是真实的阶段差异**

| | 构思阶段 | 执行阶段 |
|---|---|---|
| 找的东西 | 方向、模式、结构 | 例子、技巧、氛围 |
| query 风格 | 抽象、概念性 | 具体、感官性 |
| 高频素材类型 | arc, mechanism, question | scene, dialogue, beat, character moment |
| 对应粒度 | 画像/动态（汇总层） | 时刻/节拍（实例层） |

**2. body 中的感受/效果词是检索命中的关键**

每个 query 都包含感受或效果词。如果 body 用纯学术分析语言，embedding 距离会太远。好的 body 自然地包含创作者会用的日常语言。

**3. "已知→想知道"的 gap 是设计 body 的指南针**

创作者搜索时脑子里有 context（已知的部分），需要 inspiration（没想到的部分）。好的 body 同时触及两端——用"已知"的语义空间把创作者吸引过来，用"想知道"的内容让他们被击中。

## 五、提取流程中的需求侧审计

解析 Agent 提取完所有素材后，应做一遍**需求侧检查**：

> 假设以下每种创作者正在使用这个素材库。检查已提取的素材中是否有至少一个能帮到他们。如果没有，检查原作中是否有被遗漏的素材：
>
> - 正在设计一个有吸引力的角色
> - 正在构建有趣的世界规则
> - 正在设计一组递进的冲突
> - 正在写一个有氛围的场景
> - 正在写一段有力量的对话
> - 正在为长叙事设计持续张力的引擎
> - 正在为互动叙事准备两难选择

这个步骤确保提取不遗漏——不是按类型查漏，是按真实需求查漏。

## 六、第一批提取：以入梦创作需求为锚

以入梦（遥远的梦乡跑团项目）的真实创作需求为锚，选择第一批提取的作品和关注点。

### 入梦的核心创作需求

| 需求 | 典型 query | 对应素材类型 |
|---|---|---|
| 云少阳初到陌生世界的生存压力 | "弱者在陌生环境中的谨慎生存" | character arc, mechanism |
| 盛雨晴的"创新符箓"戏剧表现 | "非主流能力被误解为废物但其实有用" | character, mechanism |
| 张长老作为 Front 的威胁升级 | "权力压迫怎么一步步收紧" | mechanism, arc |
| 两主角从陌生人到搭档 | "被迫合作中建立信任" | relationship, beat |
| 玄鉴加载进度的长线悬念 | "缓慢揭示真相的长线钩子" | mechanism, arc |
| 仙侠表象下 VR 真相的铺线 | "嵌套世界的线索铺设" | mechanism, beat, trope |
| 每场 session 的道德困境 | "没有正确答案的两难选择" | beat, question |

### 建议第一批作品

| 作品 | 与入梦的关联 | 重点提取方向 |
|---|---|---|
| 《凡人修仙传》（前 100 章） | 修仙世界生存智慧、谨慎型主角的弧线 | character arc, mechanism（资源管理型生存） |
| 《诡秘之主》（序列 9→8 阶段） | 嵌套真相、双重身份、能力体系设计 | mechanism, setting, arc（真相渐显弧线） |
| 《冰与火之歌》（选取关键章节） | 多视角道德灰度、关系张力、权力博弈 | relationship, beat, question |
| 《巫师 3》（关键支线） | 道德困境设计、互动叙事选择 | beat, question |

### 验证方法

1. 对上述作品各跑一次故事解析
2. 拿入梦的 7 个核心 query 去检索
3. 检查：每个 query 是否至少返回 1 个有用的素材？返回的素材读起来是否"被击中"？
4. 如果某个 query 没有好的匹配——要么提取遗漏了（调提取 prompt），要么 body 写法不对（调写作规范），要么这部作品里确实没有（换作品）
